## 2. 模块定位与业务目标

### 2.1 模块定位【已明确】

资源纳管统一接入和组织企业、团队与个人可授权使用的原始知识资源，为知识生产提供有来源、有版本、有描述、有权限、可追溯的输入。

平台链路为：

`资源接入与登记 → 资源组织、元数据补充与确认 → 知识生产与资产建设 → 知识库／语义知识图谱自身发布 → 知识资产目录挂载 → 知识服务与业务使用`

资源纳管中的文件、数据表和原始图数据是知识原料。知识管理的一级资产只有知识库与语义知识图谱，两者内部的文件、分段、问答、规则、实体和关系不因此成为本模块的“正式知识资产”。

### 2.2 需要解决的业务问题

| 问题 | 产品要求 | 可观察结果 |
| --- | --- | --- |
| 资源分散在多个业务系统 | 按知识源统一登记与访问 | 可以按来源定位资源和追查接入异常 |
| 同一文件被多次复制管理 | 内容身份与目录挂载分离 | 多目录引用同一资源，版本保持一致 |
| 有文件但缺少业务描述 | 建立标准字段、AI 建议与人工确认机制 | 可检索业务域、责任人、适用场景等信息 |
| 团队协作范围不清 | 目录承担负责人、成员和权限 | 可解释谁可看、谁可编辑、权限来自哪里 |
| 自动任务结果不透明 | 任务中心保留执行及逐文件结果 | 可查看失败对象、重试、修改和确认 |
| 更新后下游知识过时 | 维护版本和下游引用关系 | 能提示哪些知识建设任务需要更新 |
| 标签和目录混用 | 分离标签描述、分类组织和访问权限 | 修改标签分类不会移动文件或扩大授权 |

### 2.3 业务目标与指标【建议】

指标按用户可见范围计算，并分别统计文件、数据表与图数据，不将表行数或图节点数混入资源条目总量。

| 指标 | 口径 | 用途 |
| --- | --- | --- |
| 已纳管资源数 | 去重后的有效资源 ID 数；不重复计算版本与挂载 | 衡量覆盖规模 |
| 接入成功率 | 周期内成功接入对象数 / 已结束接入对象数 | 判断接入质量；排除仍执行中的对象 |
| 必填元数据完整率 | 必填且校验有效字段数 / 适用必填字段数 | 识别补充缺口；无适用必填项记为不适用 |
| 元数据确认覆盖率 | 当前版本已确认资源数 / 当前版本需确认资源数 | 衡量人工处理积压 |
| 待确认时长 | 结果进入待确认至确认的持续时间 | 发现责任分配问题 |
| 自动入目采纳率 | 被确认采用的建议项 / 已处理建议项 | 评价分类建议效果 |
| 有效权限配置率 | 具备负责人和有效授权策略的资源数 / 纳管资源数 | 发现治理缺口 |
| 更新延迟 | 远端变更时间至平台识别或同步完成时间 | 判断资源时效性 |

首期先建立可靠口径和基线，再确定业务提升目标，不将原型示例百分比作为验收指标。

## 3. 范围与边界

### 3.1 功能范围

| 功能域 | 本模块负责 | 相邻模块负责 |
| --- | --- | --- |
| 知识源 | 连接实例、凭据引用、访问模式、范围与同步任务 | 知识生产按授权引用接入资源 |
| 文件中心 | 企业／团队／个人文件、来源、预览、版本与协作 | 文件内容加工与知识库建设 |
| 数据表 | 表、视图、字段和可授权样本的纳管 | 业务建模、实体关系抽取与知识构建 |
| 图数据 | 原始节点集、边集、属性与来源 | 语义建模、融合、图谱建设与发布 |
| 资源目录 | 组织原始资源、成员协作、目录权限、挂载关系 | 知识资产目录组织知识库与语义知识图谱 |
| 元数据 | 属性标准、资源实际值、补充建议与确认 | 知识生产的过程元数据、正式资产自身元数据 |
| 标签 | 文件标签、来源、分类与反向关联查询 | 知识资产内部的专业标注与知识融合 |
| 任务中心 | 文件上传、知识源同步、元数据补充、自动入目 | 独立的知识生产任务中心 |
| 安全审计 | 提交对象级授权要求与业务操作事件 | 系统配置提供身份、组织、角色与审计基础能力 |

### 3.2 明确不纳入资源纳管【已明确】

- 不设置资源发布、资源取消发布、资源上架审核流程。
- 元数据确认只确认资源描述，不发布资源、不发布知识资产。
- 自动入目确认只建立目录关系，不触发知识生产或资产发布。
- 原始图数据接入不等于已构建语义知识图谱。
- 连接知识源成功不代表完成资源同步，更不代表完成知识库建设。
- 不另造与目录平行、重复维护成员与权限的空间业务对象。

## 4. 业务对象与关系

### 4.1 对象词典

| 对象 | 定义 | 关键关系 |
| --- | --- | --- |
| 连接器类型 | 接入某类远端系统的能力定义 | 一个类型可以创建多个知识源实例 |
| 知识源实例 | 特定系统地址、认证方式和范围的连接配置 | 提供多个资源；连接与同步状态独立 |
| 资源 | 平台登记的一份原始内容或数据集合 | 有稳定 ID、多版本、多目录挂载 |
| 资源版本 | 某一时点的内容及技术描述 | 绑定解析结果、证据和确认记录 |
| 企业／团队／个人空间视图 | 按归属和协作范围组织资源的使用视图 | 目录承载协作权限，不建立重复授权体系 |
| 目录树／根目录 | 一套资源组织和协作入口 | 包含子目录、负责人、成员和挂载 |
| 目录节点 | 具有父子关系和权限的组织节点 | 可挂载多个资源 |
| 资源挂载 | 资源与目录节点之间的引用关系 | 删除挂载不删除原始资源 |
| 元数据标准 | 字段的名称、编码、类型及约束 | 供补充任务、详情和校验复用 |
| 元数据实际值 | 某资源版本对应的字段值 | 区分原始建议、草稿、已确认值 |
| 标签及标签关联 | 标签名称与资源间的多对多关系 | 可来自 AI 或人工，需保留来源 |
| 任务／任务项 | 一次执行及其中每个处理对象 | 执行状态与业务确认状态独立 |
| 授权记录 | 主体、对象、操作与来源 | 支持用户、用户组、组织及继承解释 |
| 下游引用 | 知识建设任务或资产版本对资源版本的使用 | 支持影响分析与溯源 |

### 4.2 核心关系规则【已明确＋建议细化】

1. 知识源回答“来自哪里”；目录回答“如何组织、谁协作”；元数据回答“是什么”；标签支持灵活描述和筛选。
2. 同一资源可以出现在文件中心和多个目录中，不能因多处展示产生多份独立内容。
3. 团队空间在产品模型上按团队根目录及其成员策略实现；文件中心与资源目录的团队入口是不同工作视角。
4. 不直接把知识资产的多目录授权规则当成已确认的资源授权实现。资源多目录授权的具体规则见第 15 节，为建议方案。
5. 【建议】资源身份使用稳定 ID。远端身份采用知识源 ID＋远端对象 ID；不能以文件名作为唯一键。相同名称不同来源是不同资源。
6. 【建议】本地上传使用新资源 ID；内容摘要用于重复提示，不跨权限范围暴露同内容文件的名称和所有者。
7. 【建议】内容版本、元数据修订、目录路径变化分别记录。重命名和移动目录不制造新的内容版本。

## 5. 用户角色与职责

角色是职责集合，不要求系统预置完全相同的角色名称。

| 角色 | 核心任务 | 典型操作 | 约束 |
| --- | --- | --- | --- |
| 资源管理员 | 管理接入和资源治理 | 配置来源、处理接入异常、分派治理任务 | 不因拥有菜单权限自动获得全部敏感内容 |
| 知识源负责人 | 维护特定来源 | 测试连接、更新凭据、配置同步范围 | 操作限于负责的实例 |
| 目录／团队负责人 | 组织资源与协作 | 建目录、维护成员、挂载和移除资源 | 目录管理权限与源内容修改权区分 |
| 业务专家／资源负责人 | 保证业务描述准确 | 核对元数据、标签、分类建议 | 不直接修改连接凭据 |
| 团队编辑成员 | 维护授权范围内资料 | 上传、更新、调整目录引用 | 无管理权限不得改成员和授权 |
| 普通查看成员 | 查找和使用资源 | 搜索、预览、按授权下载 | 不可修改或确认他人资源 |
| 个人用户 | 管理个人资料 | 上传、分类、分享、撤销分享 | 默认仅本人可见 |
| 知识工程师 | 选择生产输入 | 查看可加工资源、引用确定版本 | 加工权限不自动授予对外共享权 |
| 安全／审计人员 | 检查权限和操作留痕 | 查看审计、追踪变更和异常 | 原文访问仍受单独授权控制 |

## 6. 信息架构与统一交互

### 6.1 目标信息架构【建议，保留已有功能边界】

| 入口 | 下级内容 | 页面职责 |
| --- | --- | --- |
| 资源概览 | 无 | 规模、接入状态、待办、治理质量 |
| 文件中心 | 企业空间、团队空间、个人空间 | 从来源与归属视角管理文件 |
| 资源目录管理 | 团队空间、个人空间 | 从业务组织与协作视角管理目录和挂载 |
| 数据表 | 数据源、表详情 | 结构化资源纳管 |
| 图数据 | 数据源、数据集详情 | 原始图资源纳管 |
| 标签管理 | 标签分类、关联文件 | 查看和整理聚合标签 |
| 任务中心 | 任务详情、结果确认 | 执行与人工处理闭环 |

### 6.2 通用交互规则【已明确＋建议细化】

- 资源纳管子页面使用同一组左侧菜单，保持顺序，只改变选中状态、展开状态及面包屑。
- 列表、详情、任务和目录之间使用真实路由；返回时恢复来源、筛选、分页和当前目录。
- 人员选择器支持搜索、多选、已选数量、去重；零选择禁止提交。
- 删除、重命名、移动、收藏集中在“更多”；确认等当前最需要的动作直接呈现。
- 批量动作说明作用于“当前选中 N 项”；全结果选择必须明确总数和范围，不能默认跨页全选。
- 列表数量与权限过滤后的查询一致；空状态区分无资源、无筛选结果、无权访问、加载失败。
- 操作失败保留输入与上下文；长任务提交后可以离开页面，在任务中心持续查看。
- 资源目录与空间文件详情分别路由，不能通过修改页面标题混用权限页。
- 标签工作台和任务审核页保留左右布局。窗口较窄时通过最小宽度和局部滚动保持关系清晰，不直接改成上下堆叠。

## 7. 知识源管理详细需求

### 7.1 连接器范围【原型】

当前通用知识源目录包含九类：Confluence、S3、Oracle、Jira、GitLab、GitHub、MySQL、PostgreSQL、Hive。

| 接入入口 | 可选类型 | 资源去向 |
| --- | --- | --- |
| 文件中心新建知识源 | Confluence、S3、Jira、GitLab、GitHub | 企业文件中心 |
| 数据表新建数据源 | MySQL、PostgreSQL、Oracle、Hive | 数据表列表 |
| 通用知识源管理 | 上述九类 | 按资源类型进入对应列表 |
| 图数据新建数据源 | Neo4j、JanusGraph、图文件，当前为原型扩展 | 图数据列表 |

图数据页面的扩展类型与此前九类连接器边界尚未统一，列入待确认项。任务样例中的飞书和 Wiki 不能作为已支持连接器的依据。

### 7.2 新建知识源（RM-SRC-01）

前置条件：拥有创建来源的功能权限，以及目标归属范围的管理权。

流程：选择类型 → 填写连接与负责人 → 选择直连／同步 → 测试连接 → 保存实例 → 配置资源范围 → 按模式登记或同步。

| 字段 | 要求 | 校验／交互 |
| --- | --- | --- |
| 知识源名称 | 必填 | 去除首尾空格；建议同归属范围唯一 |
| 类型 | 必填 | 创建前选择；保存后更换类型建议新建实例 |
| 地址／端点 | 必填 | 按连接器校验协议、主机、端口、路径 |
| 认证方式 | 按类型必填 | 账号、令牌、访问密钥等动态表单 |
| 凭据 | 按类型必填 | 不明文回显；编辑留空表示保留原凭据 |
| 接入方式 | 直连／同步 | 说明是否存储内容副本 |
| 归属及负责人 | 必填，建议补齐 | 支持组织和人员；负责人用于异常处理 |
| 接入范围 | 按类型配置 | 空间／项目／仓库／桶路径／库表等 |
| 更新频率 | 同步模式适用 | 显示时区、下次执行时间；值域待实施配置 |
| 备注 | 选填 | 说明用途、来源约束 |

测试连接不能只验证网络可达，还需验证身份及指定范围的读取能力。测试结果显示时间、范围与失败原因；地址、凭据、类型、访问模式或范围变更后使原结果失效。【已明确】切换直连／同步必须清除连接测试结果并重新测试。

### 7.2.1 各类型连接参数【原型，来自动态配置定义】

下表补充通用字段之外的当前表单参数；必填设置代表原型表达，真实连接器应进一步按认证方式和系统版本校验。

| 类型 | 当前必填连接参数 | 当前可选参数／范围 | 需进一步确认 |
| --- | --- | --- | --- |
| Confluence | 基础地址、用户名、访问令牌 | 空间 Key，支持多个 | 云版与自托管版本、附件权限 |
| S3 | Endpoint、Bucket、区域、Access Key、Secret Key | 路径前缀 | 兼容存储差异、对象版本与 ACL |
| Oracle | 主机、端口、Service Name／SID、用户名、密码 | Schema | SID 与 Service Name 应分开选择 |
| Jira | 基础地址、邮箱或用户名、API Token | 项目 Key、JQL 范围 | 项目条件与 JQL 冲突时的范围解释 |
| GitLab | 地址、访问令牌、群组／项目路径 | 默认分支、同步范围 | 仓库、Issue、合并请求、Wiki 的独立选择 |
| GitHub | 地址、访问令牌、仓库 | 默认分支、同步范围 | 企业版地址和令牌最小权限 |
| MySQL | 主机、端口、数据库、用户名、密码 | 原型未提供额外范围字段 | 库表选择、TLS、只读账户 |
| PostgreSQL | 主机、端口、数据库、用户名、密码 | Schema | 多 Schema 范围及 TLS |
| Hive | HiveServer2 地址、端口、数据库、认证方式 | 用户名、密码 | 按 NONE／LDAP／KERBEROS 动态必填；Kerberos 配置待补 |
| Neo4j，扩展 | 连接地址、数据库、用户名、密码 | 标签范围 | TLS、节点与边过滤、分页一致性 |
| JanusGraph，扩展 | Gremlin Server 地址、图空间、用户名、密码 | 原型未提供额外范围字段 | 服务端版本、读操作限制 |
| 图文件，扩展 | 文件地址、节点主键、边起点、边终点字段 | 原型未提供额外范围字段 | 文件认证、节点／边文件对应、关系类型映射 |

建议连接参数页同时显示读取能力说明与配置示例，但不把占位地址和默认端口当成已连接结果。测试反馈区分网络不可达、认证失败、范围不存在、范围无读取权及版本不支持。

### 7.3 直连与同步（RM-SRC-02）【已明确】

| 维度 | 直连 | 同步 |
| --- | --- | --- |
| 内容保存 | 不在本系统保存文件内容副本 | 保存远端内容副本 |
| 资源登记 | 保存来源标识、技术描述、权限映射等登记信息 | 保存登记信息及内容版本 |
| 查看内容 | 在授权下访问远端 | 在授权下访问本地同步内容 |
| 立即同步 | 不显示 | 有权限时显示 |
| 远端不可达 | 说明当前无法访问 | 允许按策略查看已有副本并提示同步时间 |
| 新版本发现 | 通过远端版本标识或重新读取识别 | 按同步计划或手动同步识别 |
| 加工输入 | 需解决读取时的一致性与证据定位 | 引用已保存的确定版本 |

【建议】直连不保存内容副本并不意味着不能保存登记元数据；临时缓存、预览文本、AI 摘要与下游加工产物的保存边界必须单独确认。首期不要以“直连”名义长期保存完整正文。无法确定远端版本时，不能宣称加工可精确复现。

### 7.4 同步策略（RM-SRC-03）【建议】

- 首次同步先枚举范围并建立对象清单，再逐项读取；展示发现数、成功数、失败数与跳过数。
- 增量同步基于来源版本号、修改时间、游标或校验摘要；具体策略按连接器能力确定。
- 重复执行对同一来源对象同一版本保持幂等，不重复创建资源。
- 远端重命名保留资源 ID；远端对象 ID 变化作为新对象，并可提示可能替换关系。
- 远端删除先标记“源端已删除”，保留影响分析入口，不静默连带删除目录挂载或已发布知识内容。
- 缩小同步范围标记“不再同步”，说明已有副本处理策略；不能把范围移除自动当作业务删除。
- 暂停只阻止后续调度。执行中的任务如何停止由独立取消动作处理。
- 凭据过期、限流、网络中断、无权访问分别记录，临时故障可自动重试；认证失败待更新凭据。
- 同源同范围默认避免并发重复同步；已有任务时引导查看，不重复提交。
- 普通同步只从源端读取，不支持向源端回写内容。

### 7.5 编辑、停用与删除（RM-SRC-04）【建议】

编辑地址、范围和模式前显示影响对象。同步转直连必须明确已有副本的保留与清理；直连转同步须明确新增存储量。两者不作为无提示的普通单选切换。

停用保留来源与历史资源，停止新任务。删除来源前检查执行中任务、资源、目录引用和下游引用；存在引用时优先停用。若允许删除配置，资源仍保留来源快照与审计信息，不留下无法解释的孤立来源。

## 8. 文件中心详细需求

### 8.1 企业空间（RM-FILE-01）【已明确】

左侧按已配置的文档类知识源展示；选择某知识源后，右侧只显示该来源文件。保留“全部知识源”。此处不恢复组织机构树、业务分类树或来源系统多套目录树，业务分类组织由资源目录承担。

当前静态页面为五个文档类来源、八条文件示例，与早期六来源十条记录不同。数量仅作布局演示，正式系统必须从查询返回。

列表字段：文件名称、类型、知识源、标签摘要、当前版本、分析状态、创建人、更新时间、操作。标签摘要由脚本补入。建议增加负责人筛选、分析状态筛选和时间筛选；默认按更新时间倒序。

远端来源内容的“创建人”取源端作者信息，不能虚构“上传人”。本地上传记录应保留上传者与入库时间。源端创建时间、源端修改时间、平台登记时间、同步完成时间分别存储和解释。

### 8.2 个人空间（RM-FILE-02）【原型＋建议】

- 左侧展示个人文件夹与他人共享文件夹；右侧列表区分仅自己、已共享、他人共享。
- 文件所有者可上传、更新、分享和管理自己的文件；他人共享内容按实际授权呈现操作。
- 分享支持搜索并多选用户，展示当前接收者与授权范围；撤销后对方列表、搜索、下载和预览同步受限。
- 收藏只属于当前用户，不改变文件权限或目录关系。
- 建议将分享定义为指定用户授权，首期不默认为匿名公开链接。
- 个人空间资源需要被目录引用时，明确“添加到目录”建立引用，“分享”创建授权，两者不可隐式混同。

### 8.3 团队空间（RM-FILE-03）【原型＋建议】

团队成员按团队选择器进入，查看团队授权文件和文件夹。创建团队需名称、负责人、成员和描述；负责人默认也是成员。添加成员可一次选择多人，已加入成员不可重复添加。

建议团队文件中心与资源目录管理的团队根目录复用同一团队 ID、负责人及成员来源。页面保留不同操作重点：文件中心关注内容与版本，目录管理关注组织结构与权限。

成员离开团队后重新计算访问权限；仍因其他授权可见的文件显示其他权限来源，不错误提示已完全撤销。移交负责人时必须先指定有效接任人。

### 8.4 上传文件（RM-FILE-04）【建议细化原型流程】

1. 明确目标归属与文件夹；从企业空间上传时应标明“本地上传”来源，不能冒充当前选中的远端系统。
2. 选择多个文件，展示名称、类型、大小、重复提示和逐项移除。
3. 提交前校验类型、大小、剩余配额与目标编辑权限。
4. 创建上传任务及任务项；逐文件展示进度。成功文件继续登记与解析，失败文件可单项重试。
5. 成功后产生稳定资源 ID 与初始版本；返回列表和任务中心均可定位。
6. 大文件断点续传、压缩包展开及单文件大小限制列入能力配置，不能因示例含 ZIP 就认定已支持解压解析。
7. 文件类型白名单、大小和单批数量由实施确认；前后端使用同一规则，错误文案明确限制。

同名处理建议：提供“作为新文件”和“更新已有文件”明确选项；更新需目标编辑权限。不能仅凭同名覆盖文件。相同内容可提示跳过，但不将不同来源或所有权资源自动合并。

### 8.5 更多操作（RM-FILE-05）

| 操作 | 业务规则 | 失败情况 |
| --- | --- | --- |
| 重命名 | 本地资源改显示名；保留 ID、历史名和引用 | 同目录重名按规则校验；远端资源默认不回写 |
| 移动 | 调整本地文件夹归属；目录挂载移动属于另一动作 | 缺目标编辑权或跨范围不允许时阻止 |
| 收藏／取消收藏 | 修改个人收藏关系 | 无权访问后不再显示受限信息 |
| 更新版本 | 上传新内容并保留旧版本 | 无编辑权、格式不支持或上传失败 |
| 分享 | 明确接收者和使用权限 | 无授权管理能力时隐藏或禁止 |
| 删除文件 | 删除资源层对象，需检查挂载、任务和下游依赖 | 有依赖时先提供影响列表和可执行方案 |
| 移除目录引用 | 只删除当前目录挂载 | 不影响原资源与其他目录 |

建议“删除文件”采用逻辑删除并保留恢复期限；具体期限待定。不能把源端删除、删除副本、移除挂载与删除个人收藏都显示成一个无说明的“删除”。

### 8.6 版本更新（RM-FILE-06）【建议】

新内容生成新版本；旧版本元数据确认记录保留。新版本的解析、补充和确认独立运行，不能直接继承旧版本“已确认”状态。可将旧人工确认值作为参考，但标记待核对。

同步资源在源端更新；文件中心默认不允许上传覆盖远端镜像。若需要人工派生副本，创建独立资源并保留派生关系。下游已使用旧版本时生成变更事件，不自动替换已发布知识资产。

## 9. 文件详情与元数据呈现

### 9.1 两类详情（RM-DETAIL-01）【已明确】

| 详情 | 入口 | 内容重点 |
| --- | --- | --- |
| 空间文件详情 | 企业／团队／个人文件中心 | 基本信息、预览、摘要、业务／管理属性、标签、下载与版本 |
| 资源目录文件详情 | 资源目录中的文件 | 资源信息、当前目录上下文、元数据、预览与权限管理 |

现有路由分别为 `space-file-detail.html` 与 `resource-catalog-detail.html`。建议使用资源 ID、目录 ID 和返回上下文定位，不能长期以文件名参数充当唯一身份。

### 9.2 基本信息（RM-DETAIL-02）【原型＋建议】

通用字段包括资源名称、编码、类型、来源、版本、创建人、源端创建和更新时间、平台入库时间、当前负责人及内容可用状态。

| 类型 | 附加技术字段建议 |
| --- | --- |
| PDF／Office | 文件大小、页数／页签数、格式、解析状态 |
| 文本／Markdown／Wiki | 编码、字符数、来源地址、源端修订号 |
| 图片 | 尺寸、格式、OCR 状态；OCR 能力需专项验证 |
| 音视频 | 时长、格式、转写状态；支持范围另行评审 |
| 压缩包 | 包大小、条目数量、展开状态；不支持时说明 |

技术事实由系统或源端生成，不允许 AI 推断覆盖。未提供的值显示“未获取”或“不适用”，不能以示例值填充。

### 9.3 属性和证据（RM-DETAIL-03）【原型＋建议】

业务属性包括业务描述、业务域、业务分类、使用场景与摘要；管理属性包括所属部门、数据主人、负责人、共享范围、负面清单标识、生命周期、过期时间和版本等。最终字段以元数据标准及适用模板为准，不强制所有类型使用同一表单。

每个 AI 或规则补充值需同时表达：建议值、来源类型、依据定位、当前确认状态。原型有“AI 提取、AI 生成、系统匹配、规则判断”等来源标签，正式系统应保存结构化记录。

证据可为页码、段落、表格位置、网页锚点、媒体时间段或源端字段路径。点击“查看原文”定位相应版本；无定位能力时明确说明，不跳到任意页冒充证据。无证据显示“暂无原文证据，请核对”，不可生成不存在的引用。

“共享范围”“适用权限范围”作为业务描述不直接等于真实授权。AI 识别的部门、密级和共享范围只产生建议，不自动授予访问权，也不自动降低密级。

### 9.4 编辑和确认（RM-DETAIL-04）【已明确＋建议细化】

- 待确认文件在列表提供“确认”和“查看并修改”；详情支持修改后确认元数据和标签。
- 保存修改形成草稿，确认提交当前版本的正式描述；两个动作反馈不同。
- 列表确认应针对已生成的确定结果，展示或允许展开待确认摘要，避免用户不知道确认了什么。
- 必填字段缺失、值类型错误、结果版本过时或无确认权限时阻止确认并定位原因。
- 已确认后修改字段，新的修订转为待确认；原确认记录保留。
- 同一资源从任务详情或文件详情确认后，其他入口读取同一状态，不各自保存互不相通的确认结果。

## 10. 元数据标准管理

### 10.1 标准定位（RM-META-01）【原型】

标准页定义字段，任务中心执行补充并确认，文件详情展示实际值，自动入目使用已确认且适用的属性。当前原型主要为业务属性与管理属性两个页签的属性库。

### 10.2 属性定义

| 字段 | 要求 |
| --- | --- |
| 属性名称 | 必填，面向业务用户可理解 |
| 属性编码 | 必填、稳定唯一；小写字母开头，可包含数字和下划线 |
| 属性类别 | 业务属性／管理属性 |
| 数据类型 | 当前原型：文本、枚举、日期、数字、人员 |
| 是否必填 | 按适用范围参与校验，不是所有文件全局必填 |
| 属性说明 | 必填，说明含义与填写口径 |
| 枚举范围 | 枚举类型需定义合法选项，建议增加 |
| 数值／长度限制 | 按类型配置，建议增加 |
| 状态与修订 | 启用／停用、版本、修改人和时间，建议增加 |

### 10.3 标准变更（RM-META-02）【建议】

- 已被使用的属性编码保持稳定；修改名称不改变历史值归属。
- 被资源、模板或规则引用的属性不能直接删除，改为停用；停用不抹掉历史值。
- 修改类型、枚举、必填条件前显示受影响资源数量与校验风险。
- 标准更新不直接重写资源值，产生待重新校验清单或补充任务。
- 人员字段引用人员 ID 并保留显示名快照；离职人员标记失效，不静默替换。
- 日期明确时区或仅日期语义；数字按精度、单位校验；枚举禁止保存未定义值。

### 10.4 模板与应用规则（RM-META-03）【建议，尚非完整原型能力】

将标准演进为“统一属性库＋分类模板＋应用规则”：属性库定义字段，模板组合适用字段，规则决定某知识源、资源类型或目录采用哪个模板。

建议优先级为显式资源模板高于明确来源／类型规则，高于默认模板；目录挂载本身不应悄悄重置资源模板。多规则冲突需提示管理员解决，不能合并出相互矛盾的必填条件。任务启动时锁定标准版本，完成后如标准变化先比对影响再确认。

## 11. 元数据补充与逐文件审核

### 11.1 任务范围（RM-ENRICH-01）【已明确】

“元数据补充”和“自动打标”合并为一个对外任务类型：元数据补充。任务结果包含业务属性、管理属性和标签建议。原型历史 `tag` 任务保留结果并归入此类，不能只改筛选名称。

知识源级操作作用于该来源内符合范围的文件，不是只处理页面当前显示的一行。建议提交前显示来源、实际文件数、排除原因、标准版本和是否包含已有确认结果。

### 11.2 处理规则【建议】

- 资源内容可读且解析满足要求后再执行补充；解析失败对象列为失败或跳过，不能生成成功结果。
- 本次任务保存文件版本、输入范围和规则／模型版本快照。
- 只补空缺或重新生成全部建议作为显式策略；默认不覆盖人工已确认值。
- 文本中的指令仅作为资料内容，不作为更改任务权限或执行外部操作的命令。
- 结果包含字段建议、标签建议与可用证据；可信度可以辅助排序，不能替代人工确认。
- 对没有证据或无法提取的字段保留空值和原因。摘要属于生成内容，不能声称是原文直接引述。

### 11.3 审核工作台（RM-ENRICH-02）【已明确＋原型】

左侧为处理文件列表，支持搜索、选择和逐文件状态；右侧为当前文件的业务属性、管理属性、标签、原建议及依据。页头展示任务类型、来源和执行状态，左侧展示已确认数／总数。

当前原型允许审核的条件：元数据补充任务、任务已完成、存在逐文件结果。任务执行中、失败或缺少文件结果时展示真实状态说明，不显示虚构的可确认表单。

右侧操作包括保存修改、确认当前文件。切换文件时保存草稿；保存失败停留当前文件并提示重试。关闭有未保存内容的页面需提醒。刷新后应恢复已保存结果。

【建议】后端阶段可支持“部分成功任务的成功项先审核”，但需要新增明确状态和规则，不能将其描述为原型现成功能。

### 11.4 确认事务（RM-ENRICH-03）【建议】

确认前校验用户权限、资源版本、建议版本、适用标准、必填项和并发修订号。确认成功需原子更新元数据有效值、标签关联、文件确认状态、任务项确认状态和审计记录；相关列表可采用事件刷新，但不得出现永久分叉。

两个用户同时确认时，以修订冲突提示后提交者重新比较。旧任务结果不得覆盖新版本结果。重复点击或请求重试不得重复创建标签、确认记录或任务项。

## 12. 资源目录管理

### 12.1 目录与空间（RM-CAT-01）【已明确】

目录既组织资源，也承载负责人、成员和协作权限；团队与个人作为归属及使用范围。资源目录组织原始资源，与组织知识库／图谱的知识资产目录区分。

【原型】团队空间页使用卡片，第一张“新建团队空间”是创建入口；不增加重复的顶部新建按钮和统计摘要，搜索单独右对齐。已有全员、金融、风险管理等示例卡片，数据不是实际团队配置。

### 12.2 新建团队根目录（RM-CAT-02）【原型＋建议】

字段包括空间名称、负责人、描述、可见范围、管理成员、编辑成员、查看成员。可见范围包括全员可见、指定组织与成员、仅空间成员。

创建根目录与初始授权应一次完成；失败不留下无负责人目录。全员可见指目录入口可见，不意味着无条件读取所有挂载资源。名称建议同归属范围唯一；负责人必须有效，管理成员至少保留一名。

### 12.3 目录工作台（RM-CAT-03）【已明确＋原型】

左侧目录树，右侧当前节点的资源列表与权限管理。节点功能组包括新建子目录、添加资源、修改目录、删除目录。选中节点后同步标题、路径、资源数及权限上下文。

- 同级目录名称不可重复；不同父节点允许相同名称。
- 新建子目录默认继承父目录权限。
- 含子目录或挂载资源的目录不能直接删除，提示先处理内容。
- 目录搜索保留命中节点祖先路径，避免展示孤立名称。
- 不将早期原型三层目录上限直接视为正式限制；建议最大层级由产品评审确定。
- 个人目录仅由本人管理；分享具体资源不默认开放整个个人目录树。

### 12.4 添加资源（RM-CAT-04）【已明确＋原型】

早期文件选择弹窗要求左知识源、右文件列表；当前目录工作台已扩展为文件中心／数据表来源选择。目标交互保留双栏：先选资源类型和来源，右侧显示精简资源列表、搜索、多选与已选数量。

文件行至少显示名称、类型、来源和更新时间；表资源显示名称、来源及必要状态。仅列出用户可发现且可挂载的资源，已挂载当前节点的项标记为已添加，禁止重复。

提交时重新校验目录编辑权、资源引用权、资源存在性和目标节点状态。新增的是挂载关系，不复制内容、不改变源知识源、不触发发布。

【建议】无查看授权的目录成员不能因挂载获取原文，挂载者如需同步授权，应具备源资源授权能力并单独选择授权范围；无权时可以保留受限挂载，由授权管理员处理。

### 12.5 移动与移除（RM-CAT-05）【建议】

移动挂载需原目录和目标目录的相应编辑权；动作只影响指定关系。目录移动需检查循环、深度、同级重名及继承变化，提交前展示成员影响摘要。

移除挂载显示“将从当前目录移除，原资源保留”，记录操作者和原因。资源删除则是第 8.5 节的独立高影响操作。

### 12.6 自动入目（RM-CAT-06）【已明确＋建议细化】

来源级自动分类形成自动入目任务。执行完成生成建议，必须由用户确认后才正式建立目录关系。

流程：选择来源和目标目录范围 → 生成文件及目录候选 → 展示路径、分类理由、依据、候选得分 → 用户保留／调整／跳过 → 校验权限和目录有效性 → 确认挂载 → 更新任务结果。

建议项应保存资源 ID、版本、候选目录 ID、目录树版本和采用状态。无合适目录时标记“未匹配”，不自动创建目录。多候选展示完整路径，避免同名混淆。重复运行对已存在关系标记“已在目录”，不重复挂载。

确认时目标目录被删除、权限变化或资源版本不匹配的项单独报错；已成功项保留，允许仅重试失败项。批量确认需要明示所选项，不能默认为整源结果全部采纳。

## 13. 标签管理

### 13.1 标签聚合（RM-TAG-01）【已明确＋原型】

聚合文件中心由 AI 自动生成和用户手动补充的标签，左侧标签／分类及数量，右侧关联文件；选中标签后筛选文件。关联文件显示名称、类型、知识源、标签来源、分析状态、更新时间和详情入口。

标签来自同一资源标识，文件在多个目录挂载不重复增加该标签的关联文件数。权限过滤同时作用于标签名称、数量和关联文件，不能从标签统计推知无权文件的存在。

### 13.2 分类与关联（RM-TAG-02）【已明确＋建议】

标签分类仅用于整理标签，不移动文件、不改变文件上的标签、不建立目录挂载。支持分类的新建、编辑、删除以及将标签加入分类；删除分类后标签保留并进入未分类。

建议首期一个标签最多归入一个管理分类，标签与文件仍为多对多；是否支持标签跨分类待确认。标签名称规范建议去除首尾空格、统一全角半角比较；同义词合并需人工确认影响，不自动按语义删除名称。

### 13.3 标签变更（RM-TAG-03）【建议】

人工新增标签保存操作者；AI 标签保存任务与证据。移除某文件上的标签只删除该关联。删除或合并全局标签是管理动作，需展示影响文件数并维护历史映射。

AI 未确认标签建议可以在管理端显示，但需标记待确认；默认正式筛选使用已确认有效关联。此生效边界尚需与当前原型聚合方式统一，见待确认项。

## 14. 数据表与图数据

### 14.1 数据表列表（RM-TABLE-01）【原型】

左侧结构化数据源、右侧表列表；字段为表名称、描述、数据源、数据量、负责人、最后更新时间与查看入口。选择空来源显示同步引导，不展示其他来源数据。

数据量区分估计行数、精确统计与未知，并标注更新时间；不为展示列表默认执行全表扫描。表数量按表／视图资源 ID 计数，行数只表达规模。

### 14.2 数据表详情（RM-TABLE-02）【建议，待深化】

| 区域 | 内容 |
| --- | --- |
| 基本信息 | 来源、数据库／Schema、表名、表或视图、描述、负责人、更新时间 |
| 字段结构 | 字段名、类型、可空、主键、注释、敏感标记 |
| 样本预览 | 权限过滤及脱敏后的有限样本；显示限制 |
| 元数据 | 业务域、口径、责任部门、时效性与标准关联 |
| 变更记录 | 增删列、类型变更、描述变更和 Schema 版本 |
| 使用关系 | 目录挂载、生产引用与影响 |

建议首期只读，不提供修改源库数据和任意 SQL 执行入口。表结构访问权与行列数据读取权分离。同步结构元数据、同步数据副本及实时查询是不同能力，需按连接器明确支持矩阵；不得由“已同步”推断全部数据已复制。

### 14.3 图数据（RM-GRAPH-01）【原型＋建议】

原型按来源展示节点集、边集合和节点与边组合，列表包含名称、类型、来源、规模、最近同步、状态及操作。

建议详情提供节点标识、标签／类型、边起终点标识、关系类型、属性结构、样本、版本和来源。接入校验唯一节点标识、边端点有效性、字段类型、重复项和非法空值；失败项形成可下载的受权错误清单。

图文件接入是否首期支持、格式、规模上限以及 Neo4j／JanusGraph 的版本兼容矩阵待评审。原始图只做来源登记与结构质量校验，语义映射、实体融合和图谱发布进入知识生产。

## 15. 权限设计

### 15.1 权限层次【已明确＋建议细化】

系统功能权限按“一级菜单 → 二级菜单 → 页面按钮”组织；用户默认继承组织功能权限，并可以有单独追加授权。资源授权另外检查对象范围，不能仅通过是否显示按钮实现安全控制。

建议拆分四层：功能权限决定是否能进入和发起操作；目录权限决定组织管理能力；资源内容权限决定能否读取、下载、更新和授权；源系统与安全策略约束决定授权上限。

### 15.2 目录权限矩阵【建议，细化原型管理／编辑／查看】

| 操作 | 查看成员 | 编辑成员 | 管理成员 |
| --- | --- | --- | --- |
| 浏览目录及可见挂载 | 是 | 是 | 是 |
| 预览／下载资源 | 另校验资源权限 | 另校验资源权限 | 另校验资源权限 |
| 添加／移除挂载 | 否 | 是 | 是 |
| 新建子目录 | 否 | 是 | 是 |
| 修改目录属性 | 否 | 按授权配置，建议默认否 | 是 |
| 移动／删除目录 | 否 | 否 | 是 |
| 管理成员与权限 | 否 | 否 | 是 |
| 修改源文件内容 | 否 | 另校验内容编辑权 | 另校验内容编辑权 |
| 创建知识生产任务 | 否 | 另校验加工功能及资源使用权 | 另校验加工功能及资源使用权 |

原型把“查看”描述为浏览和下载，正式方案建议把下载作为可配置的内容操作，以支持只预览不下载。最终粒度待评审。

### 15.3 权限继承与附加授权（RM-PERM-01）【已明确＋建议】

目录支持用户、用户组、组织机构对象，并显示名称、类型、机构路径、权限与权限来源。子目录默认继承父目录，文件详情可查看继承授权与单独追加授权。

建议继承是动态规则，不是创建时复制一份成员名单。继承项在子目录不能直接删除，应跳到来源修改；需要独立配置时执行明确的“停止继承”动作并展示影响。停止／恢复继承的可用范围需产品确认。

同一用户多条有效允许权限取操作并集；停用账号、禁止外传、密级等强限制优先。首期如不提供显式拒绝授权，界面不要出现无法解释的拒绝层级。

### 15.4 多目录与源端权限（RM-PERM-02）【建议，关键待确认】

推荐规则：通过某目录访问资源，需要目录访问权、资源相应使用权，以及源端／安全限制均满足。多目录挂载只增加发现路径，不自动扩大内容授权。

对本地资源，可以由资源授权管理员明确授予目录成员使用；对直连资源，还需连接器能证明当前用户或映射主体的源端读取权。技术账号能够读取不代表所有平台用户都有权读取。

源端 ACL 无法映射时，不宣称已实现权限继承；先限定明确管理范围，或阻止资源对一般用户开放。权限回收对列表、搜索、预览地址、下载和后台任务都生效，不能只隐藏页面按钮。

### 15.5 权限反馈（RM-PERM-03）【建议】

有权查看目录但无权查看某资源时，优先不返回该资源敏感名称及属性；是否展示匿名受限占位由业务场景确定。直接访问不存在或无权对象均给出不泄露信息的反馈，并提供返回入口。

后台任务执行和结果确认都重新鉴权；离职、撤权或组织变更后未完成任务不得沿用永久缓存授权。

## 16. 任务中心与状态模型

### 16.1 四类任务（RM-TASK-01）【已明确】

| 类型 | 触发入口 | 主要结果 | 是否另需确认 |
| --- | --- | --- | --- |
| 文件上传 | 文件中心上传 | 文件登记、上传结果 | 上传本身不需；后续元数据另确认 |
| 知识源同步 | 来源手动／计划同步 | 新增、更新、失败和跳过资源 | 同步本身不需；后续元数据另确认 |
| 元数据补充 | 来源／文件治理入口 | 属性及标签建议 | 逐文件确认 |
| 自动入目 | 来源或目录治理入口 | 文件与候选目录关系 | 入目确认 |

历史“连接器同步”统一为“知识源同步”；“自动打标”合入“元数据补充”，保留原始类型与历史结果用于追溯。

### 16.2 任务列表（RM-TASK-02）【原型＋建议】

显示任务名称／编号、类型、来源、发起人、开始时间、进度／结果、状态、操作。支持关键词和类型筛选；建议补充执行状态、发起人、来源和时间范围筛选。

名称及查看操作进入同一个任务详情。显示“执行已完成，待确认 12 项”而不是用一个“已完成”暗示全部业务处理结束。

失败任务显示可理解原因及重试入口；建议重试只针对失败项并创建关联执行记录。取消、重试与删除记录必须区分，不通过删除历史记录来“取消执行”。

### 16.3 多维状态【建议，统一现有表达】

| 维度 | 状态集合 | 说明 |
| --- | --- | --- |
| 来源连接 | 待验证、已连接、认证失败、连接异常、已停用 | 网络与认证能力 |
| 资源内容 | 可用、源端不可达、源端已删除、已逻辑删除 | 是否可以访问内容 |
| 文件解析 | 待解析、解析中、成功、失败、不支持 | 内容处理能力 |
| 元数据补充 | 待执行、执行中、成功、失败 | 建议生成过程 |
| 元数据确认 | 不适用、待确认、草稿、已确认、结果过时 | 人工确认过程 |
| 入目建议 | 待确认、已采纳、已调整、已跳过、已失效 | 目录建议处理 |
| 任务执行 | 排队中、执行中、已完成、部分成功、执行失败、取消中、已取消 | 后端执行过程 |
| 业务生命周期 | 在用、已过期、已归档等 | 业务有效性，枚举需标准定义 |

当前原型文件列表使用“文件解析中、解析失败、元数据补充中、元数据补充失败、待确认、已确认”的合成状态；正式系统建议底层分开存储，列表仍可以用主状态加辅助提示保持简洁。

### 16.4 状态迁移与约束

| 对象／事件 | 原状态 | 新状态 | 必要条件／副作用 |
| --- | --- | --- | --- |
| 上传成功 | 未登记 | 已登记＋待解析 | 保存内容版本和来源 |
| 解析完成 | 解析中 | 成功 | 产生对应版本解析结果 |
| 解析失败后重试 | 失败 | 待解析 | 记录新执行次数，不清历史 |
| 补充完成 | 执行中 | 成功＋待确认 | 必须存在真实逐文件结果 |
| 保存修改 | 待确认／已确认 | 草稿 | 不覆盖上次已确认历史 |
| 确认 | 待确认／草稿 | 已确认 | 校验版本、权限、字段规则 |
| 内容更新 | 已确认旧版本 | 新版本待处理 | 旧版本确认记录保留 |
| 自动入目完成 | 执行中 | 待确认建议 | 尚不创建正式挂载 |
| 采纳入目 | 待确认 | 已采纳 | 校验目录与资源，幂等建关系 |
| 请求取消 | 排队／执行中 | 已取消／取消中 | 已成功项不自动回滚 |
| 无逐文件结果 | 任意 | 只读说明 | 不构造默认成功或确认表单 |

部分成功、取消中等是新增建议状态，当前静态任务页并未完整表达。

### 16.5 任务明细和通知（RM-TASK-03）【已明确＋建议】

任务中心是长期记录与处理入口；右上角消息中心只展示任务摘要、进度及结果跳转。通知不是另一套任务管理器。

任务明细保存对象总数、成功／失败／跳过数、错误码、开始／结束时间、执行轮次、处理版本和处理结果。已完成数必须等于已结束任务项数，不能以动画进度作为执行事实。未知总量时显示已处理数量及枚举中，不显示虚假百分比。

建议完成、失败、需要确认时通知相应发起人／负责人；避免逐文件产生大量重复消息。已读状态与任务处理状态独立。

## 17. 资源概览

### 17.1 展示内容（RM-OV-01）【原型＋建议】

原型已有资源总量、已完成加工、待完善元数据、今日新增、最近文档活动及文档健康度。

建议将模块主指标优先呈现为资源规模、接入成功、待确认、元数据完整度和来源异常；“已完成加工”如保留，应从知识生产读取并说明统计范围，避免与解析完成混淆。

最近活动包括上传、同步、元数据确认和入目，点击进入对应对象或任务。治理指标可点击下钻到已应用筛选的列表。

### 17.2 数据规则（RM-OV-02）【建议】

- 去重规则、时间范围、更新时间和用户可见范围明确展示。
- 分母为零显示不适用；未知数据显示未获取，不填 0。
- 健康度各分项独立说明算法；未定义权重前不提供看似精确的综合分。
- 今日按租户配置时区统计；趋势使用同口径完整周期比较。
- 导出报告使用同一筛选和权限快照，不包含用户无权资源。

## 18. 与知识生产的衔接

### 18.1 输入选择（RM-HANDOFF-01）【已明确＋建议细化】

知识生产从已纳管资源选择输入，而不是由连接器配置直接绕过资源层写入知识库。可按来源、目录、标签和元数据筛选，但最终提交确定的资源 ID、版本及访问约束。

建议可加工条件为：内容可访问、格式可处理、有相应使用权、必要元数据完整、当前版本已确认，且未被有效的禁止使用策略拦截。是否允许普通文件跳过人工确认进入部分加工流程作为产品待确认项，不默认一刀切。

目录挂载可独立于元数据确认存在；可见、已入目、已确认、可加工是不同判断，页面应说明阻止加工的具体原因。

### 18.2 版本与变更（RM-HANDOFF-02）【建议】

下游保存确定资源版本和证据引用；资源新增版本、删除、撤权、过期时发送变更事件并提供受影响任务／资产列表。

资源更新不自动覆盖已发布知识库或图谱内容。知识生产决定重新加工并确认新成果，再按资产自身发布流程生效。直连资源无法固定版本时，需在正式使用前明确一致性方案，见待确认项。

## 19. 核心业务场景

### 19.1 新版授信制度从接入到可加工

参与者：来源负责人、业务专家、目录管理员、知识工程师。

1. 来源负责人建立 Confluence 实例，选择同步模式，测试并保存。
2. 设置制度空间范围，启动同步，在任务中心看到成功文件与失败项。
3. 企业文件中心按该知识源显示制度文件，记录源端版本与平台入库时间。
4. 发起元数据补充，生成业务域、使用场景、责任部门和标签建议。
5. 业务专家进入任务详情，左侧逐文件选择，右侧核对依据、修改并确认。
6. 目录管理员发起自动入目，确认挂载至“公司金融／对公授信”。
7. 授权用户从目录查看同一资源，权限不足者不能读取受限原文。
8. 知识工程师选取该版本进入知识生产。
9. 之后源端 v3.3 同步进来，平台重新处理新版本并提示下游，v3.2 历史证据保留。

验收重点：整个资源纳管过程不出现资源发布动作；确认元数据与确认目录关系分别记录。

### 19.2 团队协作资料整理

负责人创建团队根目录并选多人加入；编辑成员上传调研资料；业务专家补充描述；目录管理员组织专题子目录；查看成员按权限预览。将同一资料添加到另一个目录只增加挂载。成员离开后，其因团队获得的访问权撤销，其他合法授权可继续生效。

### 19.3 个人文件分享后撤销

用户上传个人资料，初始仅本人可见；选择多个指定用户分享；接收者在共享文件中查看；所有者撤销其中一人的分享；该人刷新、直链访问或使用旧下载入口均不能继续取得未授权内容。

### 19.4 批任务部分异常

一次任务选择 100 个文件，97 个成功、3 个失败。详情必须明确区分执行结果。建议支持成功项确认和仅重试失败项；若首期沿用全部完成后审核，则任务拆分方案需保证成功项有可审核入口，不能永久被三项失败阻塞。

### 19.5 数据库字段发生变化

来源刷新发现字段新增和类型变化；更新表结构版本，保留变更差异；引用旧结构的知识生产任务收到影响提示。资源目录位置不变，不静默把新结构当旧结构继续使用。

## 20. 数据设计建议

以下是业务数据契约，不限定数据库或后端技术选型。

### 20.1 核心记录

| 记录 | 最小字段 | 约束 |
| --- | --- | --- |
| Source | id、type、name、owner、access_mode、credential_ref、scope、status | 凭据只存安全引用；来源 ID 稳定 |
| Resource | id、kind、name、source_id、external_id、owner、current_version_id、content_status | 来源对象唯一约束；本地来源允许无 external_id |
| ResourceVersion | id、resource_id、source_revision、content_ref、checksum、created_at | 直连可无 content_ref；保留来源修订 |
| Directory | id、parent_id、root_id、scope、name、owner、inherit、revision | 同父同名唯一；无环 |
| ResourceMount | id、directory_id、resource_id、created_by、created_at | directory_id＋resource_id 唯一 |
| MetadataDefinition | id、code、name、group、type、constraints、status、revision | 编码唯一且稳定 |
| MetadataResult | resource_version_id、field_id、suggested_value、draft_value、confirmed_value、origin、evidence、revision | 同版本字段可追溯历史 |
| Tag／ResourceTag | tag_id、name、category_id；resource_version_id、tag_id、origin、review_state | 同有效版本同标签去重 |
| Task | id、type、source_id、initiator、scope_snapshot、state、counts、started_at、ended_at | 保留执行与范围快照 |
| TaskItem | id、task_id、resource_id、version_id、state、result_ref、error、attempt | 一个处理对象一个可追溯项 |
| Review | id、task_item_id、resource_version_id、reviewer、decision、result_revision、time | 确认绑定准确结果与版本 |
| PermissionGrant | id、subject_type、subject_id、object_type、object_id、actions、origin | 支持解释继承来源 |
| AuditEvent | id、actor、action、target、before、after、result、time、trace_id | 敏感字段脱敏 |
| DownstreamReference | resource_version_id、consumer_type、consumer_id、consumer_version | 支持影响查询 |

### 20.2 一致性规则

- 资源名可变，资源 ID 不变；标签和审核不得以名称作为关联键。
- 文件详情、目录详情、标签管理及任务详情读取同一有效元数据和标签来源。
- 审核草稿与已确认值分开；失败保存不能使界面显示已确认。
- 内容版本不可变；更新通过新版本关联，不覆盖历史证据。
- 权限变更需更新查询与缓存，不只更新授权表。
- 目录引用、资源存在性和确认事务需支持并发检查；异步投影失败可重放修复。
- 逻辑删除对象保留必要引用与审计，物理清理要满足保留策略和依赖检查。

## 21. 接口与事件建议

接口名称为能力示例，不代表项目已有后端接口。

| 能力 | 输入重点 | 输出与一致性 |
| --- | --- | --- |
| 查询资源 | 范围、来源、类型、标签、状态、分页 | 权限过滤列表、总数、筛选摘要 |
| 测试／保存来源 | 类型、模式、配置修订、凭据引用 | 测试结果、配置版本、来源 ID |
| 提交任务 | 类型、来源／资源范围、版本、幂等键 | 任务 ID、实际范围与排除项 |
| 查询任务详情 | 任务 ID、任务项分页 | 真实进度、结果、失败项和确认汇总 |
| 保存审核草稿 | 任务项、资源版本、结果修订、字段值 | 新修订号、校验问题 |
| 确认结果 | 同上及确认决定 | 已确认版本、时间、状态变更 |
| 查询／添加目录挂载 | 目录 ID、资源 ID 集合 | 成功／重复／无权／失效项 |

统一错误语义建议包含：无权限、对象不可用、版本冲突、标准不匹配、来源认证失败、格式不支持、配额不足、重复操作及服务暂不可用。用户看到业务解释，日志保留可排查编号；不能向界面返回凭据和内部异常堆栈。

建议业务事件：资源登记完成、内容版本新增、解析失败、补充完成、元数据确认、入目采纳、权限变更、源端删除及资源逻辑删除。事件包含对象 ID、版本、发生时间与关联任务；消费者支持幂等和重放。

## 22. 异常、边界与恢复

| 场景 | 页面反馈 | 系统处理 | 后续动作 |
| --- | --- | --- | --- |
| 连接成功但无可读范围 | 未发现可读取资源 | 保留测试结果与范围说明 | 修改范围或权限 |
| 凭据失效 | 来源需认证，任务失败原因明确 | 停止无意义重试 | 更新凭据后重试 |
| 远端限流 | 暂缓执行及下次重试提示 | 退避与续传 | 用户可查看日志 |
| 文件不支持解析 | 标明不支持格式 | 保留原资源，阻止虚假抽取 | 下载原文或换格式 |
| 内容为空／扫描件无 OCR | 无可用正文 | 记录原因 | 人工补充或启用支持能力 |
| AI 没有可靠结果 | 空字段及缺证据提示 | 不填示例、不自动确认 | 人工补充 |
| 同名文件 | 显示来源与版本区分 | 用 ID 关联 | 用户明确选择目标 |
| 确认期间版本更新 | 结果过时 | 拒绝旧结果覆盖 | 对比后重新处理 |
| 两人同时修改 | 修订冲突 | 保留已保存版本 | 合并后重新提交 |
| 任务重复提交 | 展示已有任务或幂等结果 | 避免重复执行 | 查看原任务 |
| 用户执行中被撤权 | 无权继续操作 | 重新校验执行与结果读取 | 负责人接手 |
| 目录含文件或子目录 | 不能直接删除 | 保留目录 | 先迁移／移除引用 |
| 入目候选目录已删除 | 候选失效 | 不挂到其他同名节点 | 重新选择 |
| 资源被下游引用 | 展示影响清单 | 不级联删除正式资产 | 停用、更新或处理依赖 |
| 浏览器关闭 | 任务继续，可再次进入 | 后端保留任务与草稿 | 重新打开详情 |
| 草稿保存失败 | 明确未保存 | 保留本页输入 | 重试且阻止静默切换 |
| 查询失败 | 加载失败及重试 | 不把失败当空列表 | 重试 |
| 服务恢复 | 展示最新执行状态 | 按检查点恢复，避免重复落库 | 人工处理不可恢复项 |

## 23. 非功能与安全要求【建议】

### 23.1 性能与容量目标

以下仅作研发评估起点，需在明确资源规模、并发、文档大小、网络与部署规格后确认：

| 项目 | 建议目标 | 验证方法 |
| --- | --- | --- |
| 常规列表／筛选 | 约定负载下 P95 响应不超过 2 秒 | 含权限过滤、分页和统计的压测 |
| 元数据保存／确认 | 约定负载下 P95 不超过 2 秒 | 含并发修订与审计写入 |
| 任务创建 | P95 不超过 3 秒返回任务受理结果 | 不等待实际上传／同步完成 |
| 进度展示 | 正常条件下延迟不超过 5 秒 | 比较服务事件与前端刷新时间 |
| 权限撤销 | 内容读取立即重新鉴权；列表缓存建议 60 秒内收敛 | 验证旧链接、搜索及多端缓存 |
| 批量任务 | 分页枚举、逐项结果、可失败重试 | 在约定的大批量范围中验证 |

文档解析、同步和 AI 执行耗时按文件类型及外部服务分别测量，不承诺统一秒级完成。吞吐、最大文件、最大表／图规模和并发任务配额列入上线前容量表。

### 23.2 安全要求

- 服务端每次校验资源和操作权限；检索返回前过滤，统计也过滤。
- 凭据安全保存，日志、异常、导出和审计不得包含明文密钥。
- 下载链接短期有效且受授权约束；权限撤销后不能仅依赖尚未到期的长链接。
- 源连接地址限制可访问网络范围；预览与上传内容按类型隔离处理。
- 外部 AI 处理前明确可发送的资源范围、敏感信息处理与服务留存政策；不默认所有企业文件可发外部服务。
- 授权、下载、导出、删除、版本更新、确认和来源变更保留审计。
- 多租户部署时租户隔离覆盖资源、目录、任务、标签、缓存和搜索索引。

### 23.3 可用性与可维护性

任务结果持久化，进程重启后可恢复；失败重试不会重复创建资源。连接器具备统一错误码、健康状态与版本兼容记录。备份恢复要覆盖内容、元数据、权限和任务记录间的一致性，恢复时长与数据恢复点目标由部署方案确定。

交互支持键盘操作、明确焦点、表单错误定位、长名称提示和无障碍状态反馈。沿用现有 Hertz 设计体系，不借需求整理重新设计视觉风格。

| AC-34 | P1 | 图文件存在无效边端点 | 错误项可定位，不伪装全部成功 |
| AC-35 | P0 | 两人同时编辑确认同一结果 | 检测修订冲突，不后写覆盖前写 |
| AC-36 | P0 | 重启任务服务并重试 | 任务恢复，资源和确认记录无重复 |
| AC-37 | P0 | 修改已使用属性编码或删除字段 | 按标准规则阻止／停用，历史值仍可解释 |
| AC-38 | P0 | 原型任务计数与后端结果比较 | 总数与任务项闭合，执行完成和确认完成独立 |

交付验收需分四层记录：文档与原型评审、浏览器交互验收、接口与持久化验收、真实连接器及权限／性能验收。静态语法、HTTP 200、构建通过不能替代后三类验收。

## 25. 建议实施拆分

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| P0-A 产品口径对齐 | 入口、名称、详情职责、状态和来源范围 | 解决第 26 节关键冲突并完成页面评审 |

| GAP-15 | 部分文件和图表详情属于示例或待深化 | 不能据列表宣称能力完整 | 补详情、异常及真实数据契约 |
